# ADR-0003: Runtime Installation Testing

Status: Accepted

## Context

The BiodiverseR runtime build process creates standalone runtime
executables for use by the BiodiverseR package.

A successful runtime build does not guarantee that the runtime can be:

- Installed by BiodiverseR.
- Started successfully.
- Used to serve requests.
- Accessed through the BiodiverseR API.

Build-time testing alone is therefore insufficient to verify that a
runtime release is suitable for end users.

An end-to-end test is needed to validate the complete runtime
installation and startup process.

## Decision

Runtime build workflows shall perform an end-to-end installation and
startup test using BiodiverseR.

The test shall:

1. Install BiodiverseR.
2. Download or locate the runtime.
3. Start the runtime.
4. Create a BiodiverseR session.
5. Verify that the runtime responds correctly.

A successful build requires the runtime installation test to pass.

Example:

```r
library(BiodiverseR)

bd <- BiodiverseR::basedata$new(
  filename = system.file(
    "extdata",
    "example.bds",
    package = "BiodiverseR"
  )
)

stopifnot(bd$server_status())
```

## Rationale

The runtime installation and startup process involves multiple
components:

- Runtime packaging.
- Runtime installation.
- Runtime discovery.
- Runtime startup.
- Runtime communication.
- BiodiverseR integration.

Failures can occur in any of these areas even when the runtime build
itself succeeds.

End-to-end testing provides greater confidence that users can install
and use the runtime successfully.

## Consequences

### Positive

- Validates the complete user installation workflow.
- Detects runtime packaging issues.
- Detects runtime startup failures.
- Detects runtime integration issues.
- Increases confidence in runtime releases.
- Reduces the risk of publishing unusable runtime artifacts.

### Negative

- Increases CI execution time.
- Adds additional testing complexity.
- Requires installation of BiodiverseR during CI.

## Alternatives Considered

### Build-only testing

Rejected.

A successful build does not demonstrate that the runtime can be
installed, started, or used through BiodiverseR.

### Startup testing only

Rejected.

Successfully starting the runtime does not guarantee that BiodiverseR can
locate and communicate with it.

### Manual testing before releases

Rejected.

Manual testing is less repeatable and more likely to miss regressions
than automated CI testing.

## Related Decisions

- Runtime build configuration is managed through
  `.github/runtime-config.yml`.
- Runtime artifacts generated by CI are identified using source commit
  SHAs.
- Runtime release artifacts use version-based naming derived from Git
  tags.
